Disclosure Pattern: Native HTML vs ARIA

Two ways to build the same accordion/disclosure widget. Both work. Both are accessible. One requires a lot less code.

Option A: Native <details> / <summary>

Lines of code: 4. JavaScript required: none.

What is ARIA?

ARIA (Accessible Rich Internet Applications) is a W3C specification that adds meaning to the accessibility tree without changing how things look or behave visually.

<details>
  <summary>What is ARIA?</summary>
  <div class="panel">
    <p>ARIA stands for...</p>
  </div>
</details>

What you get for free:

  • Keyboard support (Enter and Space toggle)
  • Focus management
  • Correct accessibility tree (button + expanded state)
  • Browser-native open/close state
  • Works with no JavaScript

Option B: ARIA disclosure pattern

Lines of code: ~15 (HTML + JS). JavaScript required: yes.

ARIA (Accessible Rich Internet Applications) is a W3C specification that adds meaning to the accessibility tree without changing how things look or behave visually.

<button aria-expanded="false"
        aria-controls="panel-1">
  What is ARIA?
</button>
<div id="panel-1" hidden>
  <p>ARIA stands for...</p>
</div>

<script>
  btn.addEventListener('click', () => {
    const open = btn.getAttribute(
      'aria-expanded') === 'true';
    btn.setAttribute(
      'aria-expanded', !open);
    panel.hidden = open;
  });
</script>

What you have to handle yourself:

  • Toggle aria-expanded on every click
  • Toggle the hidden attribute on the panel
  • Wire up aria-controls correctly
  • Make sure state stays in sync (this is where bugs live)
The takeaway: Both versions are accessible when built correctly. But the native version is impossible to get wrong — there's no JavaScript state to drift out of sync, no ARIA attributes to forget to update. The ARIA version exists for cases where <details> isn't flexible enough (custom animations, controlling multiple panels at once, integration with a JS framework's state). For a simple show/hide? Reach for <details> first.
